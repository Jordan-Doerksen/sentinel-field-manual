MODULE 01

The Harness — Warden

READ-ONLY SHELL

A private, self-hosted AI workspace that doubles as the read-only shell hosting your whole market toolkit — and never places a trade.

Warden is the container app for the Sentinel project: a self-hosted, Odysseus-forked workspace (Python/FastAPI + vanilla JS) running in Docker at 127.0.0.1:7600. It is the shell that hosts everything else — general tools (chat, notes, tasks, calendar, documents, a memory "Brain") alongside the trading suite (Sentinel, the Underwriter desk, and a Portfolio window). Rather than launching separate programs, it runs the proven Sentinel Python engines natively, connects to IBKR/TWS itself for the live detector, and proxies to the Underwriter Rust engine. Its defining discipline is read-only: nothing in the chain ever places, modifies, or cancels an order, and it prefers a labeled blank over a fabricated number.

Functions
Self-hosted AI workspace

Local + API LLM chat with multiple model endpoints, sessions, agents/tools, MCP, skills, and per-session memory — the same chat plumbing that powers the trading reads.

Sentinel cockpit

A floating Live | Review panel: real-time order-flow detection, and a five-tab review suite over every recorded session.

Native vendored engines

The real Python engines (iceberg FSM, the v3 scoreboard, stage-2 research) run inside the process over tapes — not read from a pre-baked report, not a separate program.

Live detector + auto-record

Connects to TWS via ib_async under a supervised Watchdog, auto-records two daily windows, and auto-analyzes each closed tape so finished sessions appear on their own.

Underwriter desk

Proxies the separate Rust engine on :7601 and renders its 0DTE panels natively, polling every 2 seconds.

Portfolio window

Read-only account snapshot — positions, open orders, Net Liq, cash, buying power, unrealized P&L — piggybacked on the live detector's one IB connection.

Workspace tools

Brain (memory), Notes, Tasks (scheduled agents), Calendar (CalDAV), Library (docs), Compare (blind model tests), Deep Research.

Manual-observation journal

A whitelisted proxy that records what you already did by hand in TWS (enter / close / void). Nothing on this path reaches a broker.

Panels
  • Icon rail + Tools — launches every panel; header reads "Warden".
  • Chat — model picker, sessions, composer (web search, shell, RAG).
  • Sentinel — the trading cockpit (Live | Review, 5 tabs).
  • Underwriter — the read-only 0DTE desk.
  • Portfolio — read-only account snapshot.
  • Brain · Notes · Tasks · Calendar · Library · Compare · Deep Research — the workspace surface.
How to use
  1. One-time: clone the private repo, install Docker Desktop, launch it once.
  2. Double-click start.bat — it starts Docker, builds the container, and opens 127.0.0.1:7600.
  3. Log in with the starter admin account, then set your own password in Settings.
  4. Run TWS / IB Gateway with the API on (Read-Only, port 7497 paper / 7496 live, trusted IPs set).
  5. Navigate the icon rail: Sentinel, Underwriter, Portfolio, or the workspace tools.
  6. In Sentinel, arm Live or pick a recorded session, then read it across the tabs.
  7. Stop with stop.bat (data kept); update later with update.bat (login + tapes preserved).

Discipline
  • Read-only across the entire chain — never places, modifies, or cancels an order.
  • Honest state: a missing value renders "—" or a named state (ENGINE_OFFLINE, DELAYED), never a fabricated 0.
  • The Portfolio shows numbers only while Live is armed — never stale or fake account data.
  • The AI reads use only numbers present in the session JSON — nulls stated, thin samples flagged, no advice.
MODULE 02

The Recorder

ALWAYS-ON

A server-side flight recorder that auto-tapes the live feed during session windows and turns each closed tape into a scored, replayable review — without anyone touching a file.

The Recorder is Sentinel's always-on capture layer. A live detector stays armed 24/7 under a supervisor and streams the ES/NQ order book from TWS; during the configured ET windows it auto-saves every engine cycle to a compressed, replayable tape. It follows the detector, not the browser — closing the cockpit never stops a recording, so a tape is complete even if nobody opened the UI. The instant a window ends, the tape is finalized and analyzed into a sibling .report.json that appears on its own in the Review sidebar. No analyzer to run, no files to move.

Functions
Windowed auto-recording

Every ~1s cycle checks the ET clock; opens a tape when a window starts, records inside it, closes it the instant it ends. Outside a window it's a pure no-op.

DST-aware ET windows

NY 09:30–16:15 and Asia 18:00–03:00. The Asia tape spans midnight and is filed by its close date (Globex convention).

The tape (fmt-2 JSONL.gz)

One gzipped JSON line per cycle: L2 depth (top-10 book), IV, skew, levels, trade ticks, inside quotes — flushed every cycle, so a yanked cable keeps everything up to that moment.

On-close report

Replays the closed tape through the Signal Scoreboard and writes a sentinel.session.v1 report atomically. A report failure never breaks recording — the tape is the record.

Signal Scoreboard

Collects BREAK setups (HOD/LOD, opening-range) causally, then grades each forward for MFE/MAE and first-touch win/loss across a target × horizon grid.

The blocker

Measures order-book imbalance at each break and reports how near-flat the book was — surfacing when the book was not behind the move.

Iceberg block

Runs the absorption detector over the tape for a summary — how many breaks hidden size confirmed, rejected, or left mixed.

Auto-listing (no file moving)

Scans the live dir and the read-only Suite mount, deduped, so a fresh report shows in the sessions tab automatically.

Backfill + self-heal

On startup, writes a report for any orphaned tape and regenerates stale reports — so a session can never silently go missing.

Panels
  • Live status pill — detector state, cycle count, feed health, and the open tape's filename.
  • Review sidebar — every recorded session (symbol, window, setup count), newest first.
  • Setups table — time, direction, conviction, trigger, price, OBI, MFE/MAE, result.
  • Outcome grid & segments — win% across targets × horizons, split by trigger / conviction / blocker.
  • Replay picker — replay any tape through the cockpit at real time.
How to use
  1. Keep TWS running — the supervisor keeps the detector armed 24/7, so there's no daily start.
  2. Do nothing at the open: at 09:30 the recorder opens a tape and captures server-side.
  3. At window close it finalizes the tape and auto-generates its report — no analyzer, no file moving.
  4. Open the Review sidebar — the new session is already sitting on top.
  5. Click it to read the Setups table, the outcome grid, the blocker, and the iceberg summary.
  6. Run the Analyst, then the Council, on the same numbers.
  7. If a report ever looks missing, hit backfill (or restart) — it regenerates from the tape.

09:30:01 — first NY cycle trips the window → recorder opens es_20260708_ny.jsonl.gz. Nobody opens the cockpit; capture is server-side.
16:15:00 — window ends. End trailer written, tape closed (~23,400 cycles · ~38 MB), replayed into es_20260708_ny.report.json: 11 setups (7L/4S), ±8t@20m win 44%, median MFE +6.0t / MAE −3.0t, blocker |OBI| 0.11 (only 3/11 confirmed), iceberg 9 events.

Discipline
  • Read-only: it only writes a file about the market — never an order.
  • Report generation is best-effort; a failure is logged and skipped so recording never breaks.
  • Setups are graded causally — no look-ahead; grading only looks forward along the recorded path.
  • Show nothing rather than something false: a tape with no depth or no breaks reads as an honest blank.
MODULE 03

The Sentinel Suite

METHOD DEMONSTRATION

A read-only order-flow autopsy engine: it replays a recorded session and grades every breakout the cockpit would have called — honestly, and without ever touching the market.

The Suite is four analysis engines (PRO · STAGE 2 · ANALYST · ICEBERG STUDY) that run natively inside Warden. It replays a saved tape through the exact same Engine and detector the live cockpit uses, finds the "break" setups that would have fired inside the RTH windows (09:30–11:00 and 14:30–16:00 ET), and grades each by what price actually did next — forward MFE/MAE in ticks and first-touch win/loss across a grid of targets and horizons. Its signature finding is the blocker: at real breakouts the order book is usually near-flat rather than behind the move, so unconfirmed breaks are suspect. It answers one disciplined question — does the read actually work? — with no hindsight and no hype.

Functions
Deterministic replay + break detection

Fires breaks on high/low-of-day and 15-min opening-range crossings, only inside the RTH windows, with a 4-tick debounce. Causal — it only sees data up to the break instant.

MFE/MAE + first-touch grid

Grades forward along the real mid path: max favorable/adverse excursion, plus win/loss at ±T ticks across targets 4/8/12 and horizons 10m/20m — so no single stop is cherry-picked.

Confluence + conviction

At each break: OBI over the top 10 levels, a VWAP vote, and CVD slope over 60s. Agreement tiers the setup High / Building / Standard.

The blocker (OBI at break)

Buckets breaks as confirming / neutral / opposing at the 0.30 threshold. The recurring result: the book piles near zero — it is not behind the move.

Segmentation

Splits outcomes by trigger, by conviction, and by book state — each with N, win%, W/L/TO, and median MFE/MAE, so you see whether conviction actually paid.

Iceberg / absorption

Finds hidden-size absorption events — bid (bullish) vs ask (bearish) — with absorbed-vs-advertised ratios, and tallies which breaks hidden size confirmed.

Cross-session backtest

Flattens every setup across all sessions into one filterable pool (direction, conviction, trigger, min |OBI|, iceberg verdict) vs the all-setups baseline.

Analyst + Council reads

Feeds a compact digest to the local model: one deep Analyst review, or four persona lenses — both bound by hard honesty rules.

Panels — the five tabs
  • Analyst — the local LLM's plain-English end-of-day read in fixed desk sections.
  • Report — the scoreboard: summary, outcome grid, setups table, segments, alerts.
  • Evidence — the blocker: |OBI| at break, the distribution, per-break confluence.
  • Backtest — pool every session and filter entry rules vs baseline (with an N<5 warning).
  • Council — four AI desk personas on the same read-only scoreboard.
How to use
  1. Open the Sentinel panel; it opens on Review with the session list down the left.
  2. Launch a live recording, or pick an already-recorded session.
  3. Read the Report tab: scoreboard, outcome grid, per-setup table, segments, alerts.
  4. Check Evidence for the blocker — the OBI-at-break histogram and per-break confluence.
  5. Use Backtest to pool sessions and test filters against all setups.
  6. Generate the Analyst read, then convene the Council.
  7. Send any tab to chat, or download it as Markdown, for a written record.
Synthetic readout · illustrative only
Tape es_20260710_ny.jsonl.gz (09:31–11:00 ET, ~1,780 cycles) → 14 setups (9L/5S).
±8t@20m: raw breaks resolve 44% (7W/9L of decided), median MAE −5t / MFE +4t.
The blocker bites: median |OBI| 0.19, only 5 of 14 breaks confirming — the confirming bucket grades 4W/1L, the flat-book bucket 1W/5L. Iceberg: 6 confirmed / 2 rejected.

Discipline
  • A method demonstration, not a tradeable backtest — frictionless, mid-priced, not net of cost/spread/slippage.
  • win% is always of DECIDED setups (timeouts excluded) and paired with median MAE.
  • Segments with N<5 are greyed and flagged as too thin to read as a rate.
  • No look-ahead — the detector is causal; grading only looks forward.
MODULE 04

The Underwriter

NEVER PLACES AN ORDER

A read-only desk that watches the 0DTE S&P options market, screens same-day credit spreads, and enforces your risk discipline — but never places a single order.

The Underwriter is a decision-support and risk-control desk for selling same-day-expiry (0DTE) SPXW credit spreads and iron condors. A headless Rust/Tauri engine connects to everyday TWS with the API set to Read-Only, prices the market's expected move from the ATM straddle, screens spreads against hard rejection rules, ranks the survivors, and tracks position risk and self-discipline breakers. It exists because unconditional 0DTE selling is roughly zero-EV net of costs — so it sells selectivity and tail control, not an edge, and its UI is built to never argue otherwise. Read-only three ways over: ibapi::orders is never imported, TWS Read-Only API is on, and no command can describe an order.

Functions
Expected-move pricing

D = the interpolated ATM straddle mid; four bands from it (mean 1.00×, median 0.845×, 1σ 1.253×, 2σ 2×1σ). Broker IV never enters a time-scaling formula.

Scanner with verdicts

Builds put/call spreads and iron condors, runs 8 ordered hard-reject rules, scores Quality (Q), and stamps CANDIDATE (Q≥75), WATCH (65–75), or SKIP (declined).

Quality / Danger / Premium

Ranks on renormalized positives (alignment, premium, strike-safety, liquidity, gamma) minus a Danger term. distance_em = |spot − short| ÷ EM is the core safety input.

Risk breakers + sizing

Discipline recomputed from the journal each launch — NORMAL, COOLING (2 stops/15m), LOCKED (3 stops or day P&L ≤ −2% NLV). Sizing now from a live read-only NLV read; fails closed.

Gamma wall map

Two-layer density — green support below spot, red resistance above — dashed strongest walls and a zero-gamma band. Levels update live; the dealer sign is a fixed, labeled assumption.

Position marking + exits

After a manual entry, marks every second and runs a latched exit engine — take-profit, a debounced 2× stop, touch-stop, and standing time-exit / flatten windows.

Panels — the six readouts
  • Status — CONNECTED, data mode (LIVE / DELAYED), asof age, last error.
  • Expected Move — D headline, spot, and the four bands; scanner-gate chips.
  • Tape — RV, RI, proj-move, ρ, k-TOD, D0, and the day's open/high/low.
  • Scanner — put / call / IC tables with strikes, credit, Q, and the verdict pill.
  • Risk — breaker strip, stops today, NLV / max-contracts, and position rows.
  • Gamma — support/resistance walls, the zero-gamma band, data-age chips.
How to use
  1. Launch the engine (live / delayed / replay); it dials TWS Read-Only and idles cleanly off-session.
  2. Open the panel in Warden — it polls every 2 seconds and reserves its full layout so nothing reflows.
  3. Confirm Status: CONNECTED, the data mode, and a small asof age.
  4. Read Expected Move for how far the index can travel today and whether the gate is OPEN.
  5. Work the Scanner — use Q and the CANDIDATE / WATCH / SKIP verdict to narrow the field.
  6. Glance at Risk and Gamma for context — there is no "enter" light, by design.
  7. Place any order yourself in your own TWS, then record the fill so the desk can mark it and enforce exits.

Discipline
  • Read-only forever, enforced three ways — it never places, modifies, or cancels an order.
  • It screens and ranks; it never says "enter." SKIP means the desk declines the spread (renamed from PASS, which read as "passed").
  • Breakers recompute from the journal each launch, are monotonic in-session, and fail CLOSED.
  • Not an edge display — KPIs headline expectancy and capture, never probability-of-profit as edge.
MODULE 05

The Council

LOCAL · READ-ONLY

A panel of AI personas that each read the same thing through a different lens and argue instead of agreeing — the value is the spread, not a verdict.

"The Council" is a multi-persona review pattern: instead of one AI giving a single answer, several personas each examine the same material through their own lens and write independent takes. It exists in two forms. The in-Warden Council is a tab in the Sentinel panel — four fixed desk personas read one finished, recorded session's scoreboard on your local model. The standalone Board of Directors is a separate app where six AI models of real finance creators, plus a neutral Chair, convene on a money question you type. Both are strictly read-only and educational; neither ever places a trade or gives buy/sell advice.

Functions — In-Warden Council
Four desk personas

Risk Manager (downside — MAE, timeouts, loss clustering), Momentum Trader (follow-through — MFE, best triggers), Contrarian (what makes the read wrong — sample size), Tape Reader (order flow — OBI, iceberg, CVD). Each writes an independent ~250–400 word take.

Runs on your local model

Executed against Warden's own Ollama endpoint — no external API, no cloud, no data leaving the machine. Faster local model, deliberately distinct from the deeper single Analyst read.

Convene-all or per-persona

"Convene the council" runs all four; each card has a re-run button to refresh just one. Results cache per session and can be bundled into one document.

Functions — Standalone Board of Directors
Six finance-creator personas

ClearValue Tax, Nicholas Crown, Trade Brigade, InTheMoney, Defiant Gatekeeper, Felix & Friends — arranged in deliberate polarity pairs so the tension is the feature.

The neutral Chair

Convenes only the relevant seats, collects each take in isolation to avoid anchoring, then synthesizes with confidence-weighting — reporting the vote split and protecting the strongest dissent, never averaging.

Two ways to run

Assembles a full council prompt you either copy into Claude/ChatGPT, or "Convene live" against a local Ollama model. No install, no API key.

Report mode — the Sentinel bridge

A Sentinel-Pro session report ends with a "Questions for the Board" section naming exact seats; loading it auto-convenes them, each answering its own question grounded in that session's data.

How to use
  1. In Warden: open Sentinel, pick a recorded session, switch to the Council tab.
  2. Click "Convene the council" for all four, or the re-run button for a single persona.
  3. Read the four independent takes; optionally bundle them into one document.
  4. Standalone: open the Board of Directors app, type a money question, pick the seats.
  5. Copy the prompt into an LLM, or convene it live on Ollama.
  6. Or load a Sentinel report so the named seats auto-answer that session's questions.

Discipline
  • Interprets one finished session only — never predicts, never advises, never suggests a trade.
  • Runs entirely on your local model — no external API, nothing leaves the machine.
  • Built to disagree — forces at least one dissent, protects the minority, discounts any voice off its lane.
  • The standalone Board's personas are openly labeled AI models of public figures — not the people, not endorsements.

A day on the watch floor

One fictional session — Wednesday, 8 July 2026, symbol ES — from the open to next morning's review. Every number invented for illustration; the sequence is real.

09:30:01 ET

Window opens · recording begins

The first cycle inside the NY window trips the recorder. It opens es_20260708_ny.jsonl.gz and begins taping the book — server-side. Nobody opens the cockpit; capture doesn't need it.

09:41 ET

Opening-range break fires

An OR-hi long triggers and runs +9 ticks. The detector logs it with its conviction tier and the OBI reading at the break instant — causally, seeing only what came before.

12:18 ET

A break that doesn't work

A noon high-of-day long stalls and times out — recorded exactly the same way, because honest scoring keeps the losers.

12:40 ET

Feed hiccup · auto-recovery

TWS drops for a moment; the supervised Watchdog reconnects and the detector restarts. The tape keeps its place — and later, the startup backfill quietly regenerates the report so nothing goes missing.

16:15:00 ET

Window closes · tape scored

The clock leaves the window. The recorder writes the trailer, closes the tape (~23,400 cycles · ~38 MB), and replays it into es_20260708_ny.report.json: 11 setups, ±8t@20m win 44%, MFE +6.0t / MAE −3.0t, blocker |OBI| 0.11 (3/11 confirmed), iceberg 9 events.

16:20 ET

Session appears — no file moved

The trader opens the Review sidebar. The session is already on top, tagged ES · 09:30–16:15 · 11 setups. They read the Setups table, the outcome grid, and the blocker.

16:24 ET

The Analyst reads it back

The local model grades it 2/5: "chop dressed as breakouts — the book was near-flat at nearly every break; the only pocket of edge was OR-hi longs with a confirming book, and that's 4 setups, too thin to lean on."

16:31 ET

The Council piles on

Four lenses on the same numbers: Risk Manager flags the heat and a 27% timeout rate; Momentum notes both runners clustered in the first hour; the Contrarian dismisses the OR-hi "edge" at N=4; the Tape Reader ties the rejected breaks to absorption defending the level.

The session card shows a cached "read" flag, and its 11 setups are already pooled into the cross-session backtest — one more day of evidence, captured without anyone lifting a finger.

The through-line

It watches, scores, and reports. It never touches the market.

Read-only

No order surface exists anywhere in the stack. Not hidden, not disabled — absent.

Honest state

A blank "—" or a named state beats a fabricated 0. Show nothing rather than something false.

No look-ahead

Detectors are causal; grading only looks forward along the price that actually printed.

Thin is thin
